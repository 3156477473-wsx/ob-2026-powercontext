# 验证样例 · 深夜酒馆 · 阿九

三条手工剧本 + 一条自动化验证。剧本里的台词是**模型生成内容的示例**，你的模型可能措辞不同，但**结构**（酒名 + 台词、是否提起旧事）应当一致。

---

## 自动化验证（推荐先跑这个）

```bash
cd dify
bash scripts/start.sh      # 若后端未启动
bash scripts/verify.sh     # 另开终端
```

输出（留档 `samples/evidence/smoke.log`）：

```
PASS  health  (lore=22 memory=1 embed=hash)
PASS  首次到店：无记忆  (memory_count=0)
PASS  首次到店：命中酒馆设定  (lore_count=3 首条=黑话 · 老样子)
PASS  写入记忆  (count=1 id=mem:smoke_a:1793697679944:0)
PASS  新会话召回跨会话记忆  (memory_count=1 首条=最近连续加班到深夜，被老板在群里点名)
PASS  用户隔离  (smoke_b memory_count=0)
===== 全部通过 =====
```

它验证的是后端与 seekdb 的链路；Dify 侧的表现用下面三幕剧本核对。

---

## 剧本一：第一次到店（陌生人）

- **初始状态**：`POST /api/reset` 清空客人记忆；后端已灌入 22 条设定。
- **输入**：名字填 `林小满`，说
  > 今天加班到十一点，老板还在群里发消息，头都要炸了。
- **预期**：
  1. 先出现一句酒名，形如《加班的海》/《没回消息的夜》/《凌晨两点的回形针》；
  2. 台词 1~2 行，带酒馆设定（例如「周三半价，你这杯算我的」或「失恋专座今天空着，你要不要去坐」）；
  3. **不提任何旧事**（此时记忆为空）。
- **核对点**：Chatflow 运行记录里「取记忆与酒馆设定」节点响应 `memory_count: 0`、`lore_count: 3`。

## 剧本二：隔天再来（记忆生效）

- **初始状态**：剧本一已执行（`林小满` 有一条记忆）。
- **输入**：新开一个会话，名字仍填 `林小满`，说
  > 我又来了，老样子。
- **预期**：
  1. 「取记忆与酒馆设定」节点响应 `memory_count: 1`，`memory_block` 里出现上次「加班到十一点被老板点名」的事实；
  2. 台词里**主动提起**这件事（例如「上次你说老板在群里点名……今天他还发消息吗」）；
  3. 可能触发暗号设定「老样子」。
- **核对点**：这次回复包含上一轮的事实，而不是重新问「你怎么了」。

## 剧本三：换个人（记忆隔离）

- **初始状态**：同上。
- **输入**：名字填 `周野`，说
  > 我也来一杯，老样子。
- **预期**：
  1. 「取记忆与酒馆设定」节点响应 `memory_count: 0`；
  2. 台词**完全不提**林小满的事，按新客人对待；
  3. 若说「老样子」但没有记忆，阿九按设定上《加班的海》。
- **核对点**：`curl -s -X POST localhost:8791/api/recall -H 'content-type: application/json' -d '{"user_id":"周野","message":"老样子"}'` 返回 `memory_count: 0`。

## 恢复初始状态（重放任意剧本前）

```bash
curl -s -X POST http://127.0.0.1:8791/api/reset
# {"ok":true,"count":0}
```

设定（`dify_lore`）不会被清空；如需重灌：

```bash
cd dify/backend && npm run seed -- lore
```
